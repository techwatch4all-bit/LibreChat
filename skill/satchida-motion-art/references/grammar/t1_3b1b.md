# t1_3b1b · 3Blue1Brown-style math/concept visualization

> One-sentence grammar: **on black, show only "the one thing being explained"; smooth morphing (Transform) turns the previous concept directly into the next; color = concept name; the film almost never cuts.**
>
> Demo film: `scripts/engine/demos/t1_3b1b/` (render with `render.py --film demos/t1_3b1b`) (8s, 3 shots) · overview `assets/grammar/t1_3b1b-overview.jpg` · code `scripts/engine/demos/t1_3b1b/`

## Start-up checks

1. **Every shot states "what becomes what".** What the previous object and the next object each are (grid → circle, one curve → another, pixels → neurons). A sentence with no morphable objects does not use t1 — switch to y5 or y3.
2. **Frame 0 is the object.** Axes, grids, and curves come first; titles and formulas arrive later; do not Write a title line at second 0.
3. **Count the text on screen.** At most 2 points on screen at once; before a third appears, earlier ones either become a picture or leave. Writing points one by one into a list is black-background PPT.
4. **Write the color table first.** One color per concept; formula symbols and on-screen objects share colors; no more than 4 semantic colors in a film.
5. **Still during wait.** No uniform slow push, breathing, or floating; the camera moves only to see the next object, then stops (see ③ "camera").

## ① Where it applies

- **Use**: explaining how one mechanism "becomes another step by step" — neural network forward pass, attention, matrix transforms, gradient descent, probability distributions, algorithm flows. When the voiceover uses **action sentences** like "we flatten this grid into a column" or "each pixel is multiplied by a weight", it fits best: every sentence maps to one Transform.
- **Use**: when the audience needs to "see the math" — formula symbols and picture objects correspond one to one (the formula's W is blue; the edges are blue too).
- **Avoid**: product launches, mood/brand films (black background and white lines are too cold and slow); real data trends (that is t3's job); when the voiceover is opinion, story, or aphorism (nothing to "morph"; forcing it leaves only decoration). Quick cuts under 8 seconds do not fit either — 3b1b's native rhythm is one animation 1–3s plus a 1s hold (see ⑤), and squeezing 8 seconds into 3 shots is already the limit.

## ③ Motion paths

- **Easing**: default `smooth = 6t⁵−15t⁴+10t³` (the 3b1b version; zero velocity and acceleration at both ends; CE's is sigmoid, `MO.smoothCE`). **Almost every animation uses it**; linear only for Write, constant-speed rotation, and ShowPassingFlash's progress. `there_and_back` for Indicate; `rush_into/rush_from` for "charge in/out".
- **Default durations**: Animation run_time=1s, wait=1s. 2023–24 source statistics: explicit run_time most commonly 2s (481 uses) > 3s (333) > 1s (187) > 4s (145).
- **LaggedStart**: default lag_ratio 0.05; most used in source is 0.1. Implementation: `MO.lagged(i, n, p, r)` (the i-th occupies `[i·r, i·r+1]`, total `1+(n−1)r`). This film's 100 pixels→neurons used 0.01 (1.1s total), 160 edges used 0.006.
- **Write**: linear; 1s under 15 submobjects, else 2s; inter-object lag = `min(4/(n+1), 0.2)`; each glyph "outlines first, fills later" (`DG.math`/`DG.write`: lineDash advances the stroke → the last 60% fills and fades in while the stroke fades out).
- **Transform**: resample both shapes to equal point counts, **start-aligned** (both starting top-left, clockwise), per-point linear interpolation (path_arc=0) + color interpolation. `DG.rectPts/circlePts/morph`. Here: grid→circle (pixels→neurons), weight cells→flying into one neuron (weighted sum).
- **Entrances/exits**: FadeIn/FadeOut with shift (here 24–40px, "from below" or "fading upward"); new-layer neurons fade in from the right at 24px; replaced things shrink to a point and merge into "⋮".
- **Signal**: ShowPassingFlash (time_width 2) — copy an edge, tint yellow, width ×1.5, visible segment `[max(0,u−2), min(1,u)]`, u from 0 to 3 (`DG.flash`), staggered by input row at lag 0.04.
- **Camera**: MovingCameraScene frame animation; camera moves are events: hold → push to the next object of interest → hold. The push defaults to 3b1b's native smooth, one push (~1s, `CAM.track`'s push/to); punch (0.28s, 18–32% in; an accent, once or twice per segment) only when the conclusion lands; 3D orbits at 0.5–3°/s (3b1b default 1°/s) only when explaining spatial relations. Here shot 2's push to the output layer (1→1.08) is an event push; shot 1's uniform 1→1.025 drift around the grid is the old "slow push every shot" practice — do not copy it.
- **Still during wait**: the original is usually **still** during waits — the biggest difference from keynote-style films. No uniform slow push, breathing, or floating to pad motion; the energy comes from the next Transform.

## ④ Transitions (the common 4)

1. **Transform continuation (no cut)**: the previous shot's last frame = the next shot's first frame; morphing turns the old object into the new. Here shots 1→2: 100 pixel squares become a column of input neurons, shot 2's first frame pixel-identical to shot 1's last. This is 3b1b's number-one transition, the overwhelming majority.
2. **Camera through (zoom through)**: the camera pushes exponentially around one object (`zoom = Z^e`, constant perceived speed); the object's circumference becomes an opening with the new picture inside. `TRANSITIONS.zoomThrough`, parameters `live:true` (the old shot keeps pushing the camera past its duration, redrawing vectorially so it stays sharp), `r0` (object radius), `zoom ≥ 1100/r0` (otherwise the opening cannot cover the screen and the last frame jumps), `focus` (the new picture's subject waits centered in the opening until e>0.55, then homes). Here shots 2→3: first outline the activation-0.95 hidden neuron in yellow ("let's look at this one"), then push into it 48×, 0.75s.
3. **FadeOut(shift=UP) + FadeIn(shift=UP)**: on topic change everything fades upward and the new content fades in from below (`TRANSITIONS.fadeShift`).
4. **ReplacementTransform for titles/formulas**: the old formula's symbols move to the matching symbols' positions in the new formula (TransformMatchingTex, 3b1b default 2s); unmatched symbols cross-fade.

## ⑤ Rhythm and text

- **Shot lengths**: the original is continuous scenes; a single animation runs 1–3s followed by a 1s wait; one "shot" (one concept) often runs 8–20s. This film's 8 seconds over 3 shots (2.6/2.8/2.6s) is a **compressed version**; in real voiceover use, stretch it 2–3×.
- **Counterpoint with the voiceover**: Grant's process is **animate first, record voiceover later** ("I start by laying out all of the animations… then once I record the voiceover, the actual editing is like a day"). So the counterpoint rule is "one sentence = one animation": the animation starts when the sentence speaks its action verb, lands at sentence end, then waits ~1s for the audience.
- **Text**: titles/questions are Written before the action (ask first, then show); formulas appear with the picture and share its colors; values (0.95) follow the fill count, never preceding the picture. One screen holds at most one title line plus one annotation line.
- **FAQ principle**: "Every movement on the screen should be deliberate, with an identifiable purpose" — motion without an explanatory purpose gets cut.

## ⑧ The 3 easiest mistakes

1. **Treating "glow" as 3b1b's signature and adding bloom or a deep-blue gradient background.** The original is pure black + high-saturation thin lines + ×1.5 saturation, almost no halo. Add a halo and it becomes a "tech-feel PPT".
2. **All linear or generic easing, animations fast and numerous.** The default must be smooth (the quintic polynomial); one animation 1–3s then a 1s hold; every action maps to one verb in the voiceover.
3. **Switching the color code mid-film / too many colors.** One color = one concept; formula symbols and picture objects share colors; beyond 3–4 semantic colors the audience stops tracking.
